# WMS 独立增量脚本

`wms-mobile-inbound-receipt-pg.sql` 为移动收货新合同提供永久原请求表、唯一键、状态约束及终态保护触发器。依赖现有 `mom_wms` schema，不新增菜单或角色权限。

发布顺序：

1. 在隔离 PostgreSQL 备份并预演脚本，核对重复执行、终态不可改写/删除，以及并发登记和撤销。
2. 正式发布窗口停止 WMS 收货写入，备份后执行脚本；任一步报错回滚整个事务。使用既有数据库连接执行 `psql -v ON_ERROR_STOP=1 -f wms-mobile-inbound-receipt-pg.sql`，不把口令写入脚本。
3. 发布 WMS 服务，再发布配套 APP。只有接入新 `/app/inBill/receipts` 合同的页面获得永久原号保护，旧调用保持兼容。
4. 使用受控通知分别核对分批收货、完成后过账、重复提交、同号异内容、超时查询、原号撤销及账号/工厂隔离；对照通知、入库单和库存流水数量。

`CONFIRMED` 确认本次收货数量已登记，不代表部分通知已全部过账。`CANCELLED` 只封存尚未执行的原请求，不回冲已执行的业务。`NOT_CONFIRMED` 不能证明旧请求不会稍后成功，只能继续查询、按原号原文重试或安全撤销。

此表无失效时间、逻辑删除和常规清理功能；终态是后续网络重试的永久凭证。升级前不可把新 APP 用于正式收货。代码回归使用 H2 PostgreSQL 模式；2026-10-30 已在 `kitex_mom` 实测 PostgreSQL 终态保护，并通过其他入库分批收货、原号重放、异内容拒绝和安全撤销。真机及其他业务类型的实库验收仍须逐项完成，记录见 `outputs/20261030_wms_runtime_receipts/`。

## 移动出库永久回执

`wms-mobile-outbound-receipt-pg.sql` 为生产领料、销售出库和其他出库提供独立永久原请求表。通知明细与实际库存分别记录，库存行被消耗或删除后仍能查询原回执。依赖现有 `mom_wms` schema，不新增菜单或权限；不能用入库回执表代替。

发布顺序：

1. 在隔离 PostgreSQL 备份并预演脚本，核对重复执行、唯一键竞争、终态不可改写/删除，以及出库与撤销争用同一请求号的结果。
2. 正式发布窗口停止 WMS 出库写入，备份后执行 `psql -v ON_ERROR_STOP=1 -f wms-mobile-outbound-receipt-pg.sql`。脚本失败须整体回滚，数据库口令通过既有连接管理提供。
3. 发布 WMS 服务，再发布配套 APP。新页面使用 `/app/outBill/receipts`，旧接口保留兼容并校验实际组织、原仓操作权限，按原通知业务分发；旧调用没有请求号，不获得永久重试保证。
4. 使用生产领料、销售出库及其他出库的受控样例，逐笔核对通知余量、执行明细、实物库存、销售预留、拣配和事件记录。重点验证同一通知/库存的多次部分出库、重复与并发提交、响应丢失恢复、权限撤销及原号撤销。

`CONFIRMED` 表示本次库存扣减和拣配登记已经提交，不表示承运交接、客户签收或财务过账。`CANCELLED` 只封存尚未执行的原请求，不冲回已经扣减的库存；`NOT_CONFIRMED` 仍须原号核对、原文重试或安全撤销。新精确出库按本次执行建立独立明细，以免不同部分出库共用预留消费去重键。

2026-10-30 已核对 `kitex_mom` 中此表、约束、启用的触发器与函数体均匹配脚本，并以真实其他出库验证两次部分出库、原号重放、安全撤销及来源库存消耗后的原结果核对。对应实库入库流水 4、出库流水 4、结存 0；其他出库类型、实际设备和弱网验收仍须逐项完成。永久终态记录不可纳入普通数据清理任务。

## 生产退料结束收货永久回执

`wms-return-finalize-receipt-pg.sql` 为生产退料“结束收货／申报差异”提供独立永久原请求表，沿用现有 `wms_return_receipt_finalize` 权限，不新增授权。此操作可能将待完成的退料入库单实际入账并回补预留，必须与终结回执同一事务提交。普通收货回执不能代替终结回执。

1. 在隔离 PostgreSQL 预演脚本，核对重复执行、原请求唯一键竞争、终结与撤销竞争、终态不可更新或删除。
2. 停止 WMS 退料收货和终结写入，备份后执行 `psql -v ON_ERROR_STOP=1 -f wms-return-finalize-receipt-pg.sql`。表依赖当前生产退料入库、不可变履历及 Outbox 的既有结构，不能只升级此表而缺少原业务表。
3. 先发布 WMS，再发布 APP。旧 `/wmsProduceReturn/receipt/finalize` URL 也进入新表保护，故本次服务发布前必须执行脚本；旧 URL 仍返回当前业务 View。新 `/finalize/commands` 返回封存的当次终结结果，后续异岗差异处置不会改写它。
4. 核对足额、短收、溢收、无实物、两张部分收货单、多次原号重试、响应丢失、通知作废及账号/工厂隔离。对照实物库存、入库单、预留回补、不可变履历、Outbox 和新永久回执；任一持久化失败须整体回滚。

`CONFIRMED` 表示该次结束收货及当时差异状态已在 WMS 提交，不代表 MES 已受理回执。`CANCELLED` 封存尚未执行的终结请求，不撤销已完成入账。历史原请求已存在履历时，仅原操作人、原通知、原仓、溢收和原因可证明一致，才补封存原结果；证据缺失时拒绝自动办理，须核对原履历。

2026-10-30 已在 `kitex_mom` 核对本表、约束与保护函数，并以回滚探针验证 PostgreSQL 终态不可改写或删除。退料终结业务正向联验尚未完成：当前库没有 MES 生产退料通知，且四项专用权限未注册，接口返回 403。旧累计 v2 第172节只从不带仓库后缀的 `wms_notice_inout_return` 寻找父菜单，当前菜单都带仓库后缀，导致旧脚本跳过权限注册；需按仓库菜单生成与同步规则补齐，再给测试角色明确授权。此次没有修改角色授权。H2 的真实退料/预留/Outbox 回归仍不能代替这项实库业务验收。该表同样不得配置常规删除或过期清理。

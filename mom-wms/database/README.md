# WMS 独立增量脚本

`wms-mobile-inbound-receipt-pg.sql` 为移动收货新合同提供永久原请求表、唯一键、状态约束及终态保护触发器。依赖现有 `mom_wms` schema，不新增菜单或角色权限。

发布顺序：

1. 在隔离 PostgreSQL 备份并预演脚本，核对重复执行、终态不可改写/删除，以及并发登记和撤销。
2. 正式发布窗口停止 WMS 收货写入，备份后执行脚本；任一步报错回滚整个事务。使用既有数据库连接执行 `psql -v ON_ERROR_STOP=1 -f wms-mobile-inbound-receipt-pg.sql`，不把口令写入脚本。
3. 发布 WMS 服务，再发布配套 APP。只有接入新 `/app/inBill/receipts` 合同的页面获得永久原号保护，旧调用保持兼容。
4. 使用受控通知分别核对分批收货、完成后过账、重复提交、同号异内容、超时查询、原号撤销及账号/工厂隔离；对照通知、入库单和库存流水数量。

`CONFIRMED` 确认本次收货数量已登记，不代表部分通知已全部过账。`CANCELLED` 只封存尚未执行的原请求，不回冲已执行的业务。`NOT_CONFIRMED` 不能证明旧请求不会稍后成功，只能继续查询、按原号原文重试或安全撤销。

此表无失效时间、逻辑删除和常规清理功能；终态是后续网络重试的永久凭证。升级前不可把新 APP 用于正式收货。当前代码回归使用 H2 PostgreSQL 模式验证真实 mapper 与事务，PostgreSQL 触发器及真机验收尚待执行。
